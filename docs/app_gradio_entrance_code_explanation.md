# `scripts/app_gradio_entrance.py` 代码详细说明

本文档用于解释 `scripts/app_gradio_entrance.py` 的整体结构、各模块职责、推理流程，以及关键代码行的作用。该脚本是一个基于 Gradio 的可视化演示程序，用于展示 YOLOv10 + EntranceDetect 停车位入口线检测模型，并可选地调用 MobileNetV3 对车位占用状态进行分类。

## 1. 程序整体作用

`app_gradio_entrance.py` 做了四件事：

1. 加载 EntranceDetect 检测模型权重，输入图片后预测停车位入口线、车位主体方向、车位类型和检测置信度。
2. 根据入口线端点和主体方向，恢复完整车位四边形区域。
3. 可选地把车位四边形透视变换成固定尺寸小图，再用 MobileNetV3 判断车位是否空闲或占用。
4. 通过 Gradio 提供单张图片检测、批量图片检测、参数调节和结果下载界面。

整体推理链路如下：

```text
用户上传图片
  -> Gradio 事件调用 run_single 或 run_batch
  -> make_params 读取界面参数
  -> get_pipeline 加载或复用模型
  -> EntranceParkingDemo.predict 执行检测
  -> build_slot_quad 恢复车位四边形
  -> 可选 warp_patch + classify_patch 判断占用状态
  -> draw_detection 绘制入口线、方向箭头、四边形和标签
  -> 返回可视化图片、统计文本或 ZIP 结果包
```

## 3. 模型输出字段解释

在 `predict()` 中，模型输出的每一行 `row` 被解释为一个检测结果：

| 字段 | 含义 | 本脚本用途 |
|---|---|---|
| `row[0:4]` | YOLO 检测框坐标 | 可选绘制检测框 |
| `row[4]` | 检测置信度 | 过滤低置信度检测、显示平均置信度 |
| `row[5]` | 标准 YOLO 类别或占位字段 | 当前脚本未使用 |
| `row[6:10]` | 归一化入口线端点 `(x1,y1,x2,y2)` | 转成原图像素坐标后绘制入口线 |
| `row[10:12]` | 归一化主体方向向量 | 计算车位深度方向和方向箭头 |
| `row[12:15]` | 车位类型概率 | 取最大值作为 `rect`、`rect-long` 或 `acute/obtuse` |

需要注意：检测阶段会先把图片 resize 到 `imgsz × imgsz` 输入模型，但入口线端点是归一化坐标，所以恢复到原图时直接乘以原图宽高即可。

## 10. 验收讲解建议

向老师演示时可以按下面顺序讲：

1. **模型部分**：本程序加载的是训练好的 EntranceDetect 权重，模型直接输出入口线端点、车位方向和车位类型。
2. **几何恢复部分**：通过 `build_slot_quad()`，用入口线和方向向量恢复完整车位四边形，因此可以显示车位区域。
3. **占用分类部分**：如果开启分类，就用透视变换把车位区域拉正，再送入 MobileNetV3 判断空闲/占用。
4. **可视化部分**：红色表示占用，绿色表示空闲，蓝色/青色表示未分类；箭头表示车位主体方向。
5. **交互部分**：Gradio 支持单图和批量检测，批量检测还能打包下载结果。

## 11. 需要注意的实现细节

1. `scripts.train_entrance_yolo` 虽然没有直接调用函数，但不能随便删除，因为它负责注册自定义模块。
2. `predict()` 没有使用标准 YOLO `Results` 对象，而是直接调用 `self.model.model(x)`，原因是自定义 head 输出了入口线、方向和类型字段。
3. `STATE_NAMES` 当前没有被实际使用，绘制文本使用的是 `STATE_LABELS`。
4. `row[5]` 当前没有被使用，这是因为该 demo 关注入口线检测结果，而不是标准 YOLO 类别字段。
5. 分类器是可选模块；没有分类权重时程序仍然可以正常做入口线检测，只是占用状态显示为 `unknown`。
6. 输入尺寸默认 `608`，和模型训练/stride 对齐有关；界面保留了 `512/608/640/768` 选项，便于速度和精度权衡。
